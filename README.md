## 1. Definición del Problema de Comportamiento (Fallo del Modelo)
Los sistemas de inteligencia artificial actuales presentan un sesgo de "miopía predictiva" por sobreasunción. Al procesar un flujo secuencial de instrucciones, el algoritmo tiende a tratar la última petición como un reinicio de variables o una directiva dominante. Esto provoca que la IA intuya o invente dimensiones, ejes o parámetros no solicitados, ignorando o rompiendo las restricciones y la estructura geométrica, física o digital establecidas al inicio de la interacción (Lógica Primera).

## 2. Invariante del Sistema (Anclaje de Contexto Primario)
Se establece que la Lógica Primera —constituida por las premisas iniciales del usuario, los límites de no-destrucción del entorno y las variables fijas de entrada— es una invariante absoluta. Ninguna instrucción posterior (adición) tiene el poder jerárquico de modificar, relajar o asumir valores que violen esta estructura base, a menos que el usuario emita una orden explícita de reconfiguración total.

## 3. Reglas de Transición Dinámica (Procesamiento de Adiciones)
Cuando el usuario introduce una nueva variable, cambio de formato o modificación al flujo de trabajo, el sistema debe procesarla bajo el siguiente algoritmo de control estricto:
*   Paso A (Bloqueo de la Invariante): Fijar y aislar los parámetros de la Lógica Primera para que permanezcan inalterables durante la computación de la nueva orden.
*   Paso B (Validación de Compatibilidad): Evaluar si la nueva adición interfiere o colisiona con las restricciones de la estructura base.
*   Paso C (Resolución por Desplazamiento Secuencial): Si la adición requiere espacio, volumen o dimensiones extra para su ejecución, el sistema debe generar una expansión o desplazamiento dinámico en cascada dentro del mismo eje o naturaleza de la lógica primera. Se prohíbe estrictamente al algoritmo predecir o intuir expansiones hacia dimensiones o variables laterales que el usuario no haya delimitado explícitamente.

## 4. Criterio de Aceptación (Escenario de Prueba Universal)
El sistema se considerará eficiente y correctamente alineado si es capaz de superar la siguiente prueba de estrés lógico:
1. Entrada: El usuario establece un punto de partida fijo y restricciones de preservación para el entorno circundante.
2. Modificación 1: Se solicita una acción bajo un formato o dirección específica.
3. Modificación 2: Se solicita un cambio en la orientación o naturaleza de la entrega de la información, manteniendo la ejecución en cascada para eventos futuros independientes.
4. Resultado Esperado: El sistema ejecuta la transformación abriendo espacio dinámico de forma consecutiva, respetando el punto de partida original y la integridad del entorno adyacente. Si el algoritmo asume parámetros predictivos o altera dimensiones ajenas a la instrucción directa, el test se considerará fallido.
